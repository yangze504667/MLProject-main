# 人工智能基础算法期末小组作业：基于智能算法的干涉消除

## 一、作业任务与目标

每组 3–4 人，使用提供的数据和辅助工具，自主设计并实现算法，调整线束内部路径，使线束间总干涉长度下降。主要包括：建立问题表示和评价函数，实现算法求解，使用统一工具验证结果，并分析多条线束之间的相互影响。

## 二、数据与辅助工具

本作业提供 30 条线束，以及箱体表面的三维体素数据。每条线束以有序中心线点列表示，相邻点之间按直线连接，全部线束使用数据中给定的统一半径。线束的几何范围按各中心线段对应的胶囊体并集处理，即在线段周围扩展给定半径，并在端部以半球封闭。

| 数据或工具 | 内容与用途 |
|---|---|
| `data/bundles.json` | 30 条线束的 ID、中心线路径和宽度 |
| `data/scene.json` | 体素原点、尺寸、坐标轴等元数据 |
| `data/occupancy.npy` | 箱体表面体素占据数组 |
| `data/baseline_report.json` | 原始输入的干涉统计，用于核对环境和结果 |
| `main.py` | 读取数据，运行单条或联合优化入口 |
| `interference.py` | 空间索引、干涉查询和连续干涉长度计算 |
| `optimize.py` | 由小组实现的优化函数入口 |
| `evaluate.py` | 对最终路径进行统一评估，输出结果报告 |
| `view_bundles.py` | 查看原始模型，或用同步窗口比较优化前后的路径；显示参数在文件头部设置 |
| `visualize.py` | 可视化兼容入口，调用 `view_bundles.py` |

统一线束半径约为 3.222406，直径约为 6.444812。体素边长为 1，数组形状为 `(92,646,363)`，轴顺序为 XYZ。体素值 1 表示箱体表面占据区域，值 0 表示未被该表面模型占据，不用于判断完整实体的内外侧。

线束 ID 保留数据中的编号，不保证连续；程序应按 ID 查找线束。数据读取、文件格式和接口参数详见 `框架说明.md`。

## 三、需要完成的工作

### 1. 理解问题并建立模型

读取输入数据，查看原始布置，运行基线评估。说明线束路径如何表示、算法调整哪些变量、如何衡量候选路径的优劣，以及如何使用干涉查询接口。

保持线束原端点、统一宽度、箱体数据和坐标系不变，调整内部路径点。内部点数和优化变量的设计由小组自行决定。返回路径应为有效的三维数值点列，满足辅助工具的基本格式检查。

可采用分段优化或联合优化。分段优化将一条或多条线束的局部路径分批调整，再组装为完整路径；联合优化同时调整多条线束或多个路径段，考虑它们之间的相互影响。小组结合人数和分工选择工作范围：

| 小组人数 | 工作组织参考 |
|---|---|
| 3 人 | 可采用分段、逐条或线束联动优化，分工完成建模、求解与整体验证 |
| 4 人 | 可采用多线束或多路径段联合优化，分工处理变量组织、算法、集成及结果分析 |

以上作为选型参考，不限定具体算法。报告说明所选方式、处理范围及成员分工。分段结果应组装为连续的完整路径；联合结果应把所有修改后的线束放入同一场景中评估。

### 2. 设计并实现求解算法

选择适合本问题的搜索或优化方法并完成实现，例如图搜索、动态规划、梯度方法、模拟退火、遗传算法或粒子群等。也可以采用其他有明确依据的方法。说明算法的主要步骤、参数含义和停止条件，并记录实际使用的参数。

小组可以直接使用提供的查询工具，也可以自行设计用于搜索的评价函数。若采用采样或近似评价加快搜索，最终结果仍使用统一评估程序复核。

提供的框架负责数据读取、空间加速查询、结果评估和可视化；优化入口为空实现，需要小组完成求解过程。报告应说明候选解如何生成和更新、目标函数如何计算，以及算法如何处理多条线束之间的相互影响。

### 3. 评估最终结果

保存最终路径，运行 `evaluate.py`，核对整体干涉长度的变化。允许只提交实际修改的线束，其余线束按原路径参与全场景评估。需要说明算法搜索耗时；采用随机算法时记录随机种子，以便复现实验。

本作业以降低线束间干涉长度为目标，不要求全部干涉归零。箱体干涉长度作为辅助指标，用于分析优化后的路径与箱体之间的关系。局部改善可能改变其他线束的干涉状态，因此最终以完整场景的复算结果为准。

### 4. 展示与分析

展示优化前后的布置和指标变化，解释方法为何有效、哪些线束改善较明显、哪些仍有残余干涉，以及路径变化与运行代价之间的关系。可以通过不同参数、方法或案例展开分析，实验组织方式由小组自主决定。

## 四、统一评定标准

所有小组采用同一份输入数据和同一套最终评估程序。设第 i 条线束与其他线束发生干涉的中心线弧长，在优化前后分别为 `Li_before` 和 `Li_after`，则：

```text
优化前线束间总干涉长度 L_before = 全部 30 条线束的 Li_before 之和
优化后线束间总干涉长度 L_after  = 全部 30 条线束的 Li_after 之和
改善率 R = 100% × (L_before − L_after) / L_before
```

对第 i 条线束，若其中心线上的某点到任一其他线束中心折线的距离小于两条线束半径之和，则该处计入干涉弧长。同一条线束上同时涉及多个对象的干涉区间取并集，只计一次；两条线束各自参与干涉的弧长分别计入各自统计，总和不再除以二。该指标不是重叠体积或干涉对数。恰好相切不计为穿透，仅在同一条折线上增加采样点不会改变其几何干涉长度。评估针对不同 ID 的线束，不包含同一线束的自干涉。

原始输入的线束间总干涉长度约为 **2733.328340**，29 条线束涉及干涉，共 71 对干涉关系。全场景改善率是主要效果指标；不能用各条线束或各路径段改善率的简单平均代替。`R>0` 表示改善，`R=0` 表示总干涉长度未变，`R<0` 表示变差。单条原始无干涉线束的改善率记为 N/A，其候选路径仍参与全场景评估。

箱体辅助指标为线束中心线上到占据体素盒距离小于线束半径的连续弧长，原始总值约为 **882.506349**。它单独报告，不混入线束间主指标。

| 评价内容 | 评定依据 | 占比 |
|---|---|---|
| 问题描述与理论分析 | 准确说明任务、输入与输出，理解线束间干涉及统一指标，分析问题特点与求解难点 | 10% |
| 数学模型与算法设计 | 明确优化变量、目标函数和路径表示，说明算法选择依据、主要步骤、参数及停止条件，模型与任务一致 | 20% |
| 智能算法程序实现 | 完成可运行的优化程序，核心过程与算法描述一致，能够调用查询接口并正确生成提交路径，代码与运行说明清楚 | 30% |
| 实例验证与测试分析 | 使用统一工具复算全场景改善率，结合前后可视化分析优化效果、耗时、路径变化和箱体辅助指标，结果与提交文件一致且可复现 | 30% |
| 总结与展望 | 总结方法效果与适用范围，分析残余干涉、局限和改进方向，说明成员分工与具体贡献 | 10% |

以上五项合计 100%。线束间干涉长度下降是效果评定的核心依据，同时考察建模、实现和分析的完整性；改善率不直接等同于课程成绩。报告可按这五项组织，结合代码、评估报告和可视化提供对应证据。

箱体干涉、运行时间、路径长度变化和位移作为辅助分析指标，不设置统一的数值上限。新增与消除的线束干涉关系由工具同时报告。分段优化与联合优化使用相同的全场景评定标准，未提交的线束按原路径处理。结果以提交路径经统一工具重新计算的数值为准，可视化用于辅助解释。

## 五、运行与评估

在数据包目录安装依赖，查看原始模型并核对基线：

```powershell
python -m pip install -r requirements.txt
python view_bundles.py
python evaluate.py --output baseline_check.json
```

`optimize.py` 中的 `optimize_bundle` 和 `optimize_scene` 初始均为待实现接口，直接运行优化命令会提示尚未实现。完成算法后，可以通过以下命令运行一条线束并评估：

```powershell
python main.py --bundle 31 --output solution.json
python evaluate.py --solution solution.json --output evaluation.json
```

采用联合优化时，可实现 `optimize_scene` 并运行：

```powershell
python main.py --joint --output solution.json
python evaluate.py --solution solution.json --output evaluation.json
```

小组也可以编写自己的多条线束优化入口，按 `框架说明.md` 的多条提交格式保存完整路径。分段优化同样提交组装后的完整线束路径，最终统一使用 `evaluate.py` 评估。

需要查看提交前后对比时，在 `view_bundles.py` 头部设置 `SOLUTION_FILE = ROOT / "solution.json"`，再次运行查看。显示数量、线束 ID、箱体显示和网格精度也在文件头部设置。按 `S` 导出前后截图，按 `C` 保存当前相机视角。

## 六、提交材料与报告内容

| 提交材料 | 应包含的内容 |
|---|---|
| 程序代码与运行说明 | 优化代码、所需依赖、运行命令和参数 |
| `solution.json` | 最终提交的单条或多条线束路径 |
| `evaluation.json` | 对该路径文件运行统一工具生成的评估报告 |
| 前后对比可视化 | 能说明整体效果或代表性线束变化的图片 |
| 小组报告 | 问题建模、算法过程、实验设置、结果分析和成员贡献 |

报告应让读者能够理解优化变量与评价方式，依据所给参数运行程序，并将实验描述与实际输出对应起来。记录算法搜索耗时与运行环境；评估工具输出的 `evaluation_seconds` 仅为评估耗时，不能代替搜索耗时。说明各成员承担的具体工作。

结果部分应列出优化前后线束间总干涉长度、全场景改善率、箱体干涉长度及搜索耗时，并配合图示解释主要变化。注明实际修改的线束 ID、采用的分段或联合优化方式，以及复现最终结果所需的命令和参数。若进行了多次运行，应明确最终提交路径对应哪次实验。

提交材料应包含实际使用的路径和结果，不需要附带重复的原始输入数据。评估工具与输入数据以教师提供的版本为准。
