# 程序与接口说明

核心框架分为读取（`main.py`）、建立索引与查询（`interference.py`）、优化（`optimize.py`）三个文件；另提供独立评估和可视化工具。线束间干涉为主指标，箱体干涉为辅助指标。提供单条和联合优化两个待实现入口。

## 数据读取和索引

```python
from main import load_data
from interference import InterferenceIndex

bundles, occupancy, scene = load_data()
queries = InterferenceIndex(bundles, occupancy, scene)
bundle = next(item for item in bundles if item["id"] == 31)
```

每条线束是 `{"id": int, "radius": float, "points": (N,3)数组}`。文件内只存全局宽度与半径，读取后为各条线束附上同一个半径。坐标单位为毫米，体素轴顺序为 XYZ。ID 保留聚类筛选结果，不保证连续。

## 查询与效果评估

```python
queries.query_cables(31)
queries.query_cables(31, other_id=22)
queries.cable_collision_length(31)
queries.cable_collision_length(31, other_id=22)
queries.query_cables(31, points=candidate)
score = queries.evaluate_cables(31, candidate)

# 箱体辅助指标
queries.query_chassis(31, points=candidate)
queries.chassis_collision_length(31, points=candidate)
box_score = queries.evaluate_chassis(31, candidate)
```

`candidate` 是 `(N,3)` 数组。候选查询不会更改原索引；`query_cables` 此时比较候选路径与其他原路径。多个路径同时改变后的线束间关系，应交给独立评估工具重建索引检查。

查询空列表表示未发现严格穿透，相切允许。默认箱体查询只返回一个命中，线束查询对每个其他线束返回一个命中；`max_hits=None` 可返回全部命中。默认命中数不是全部线段或体素碰撞数量。

`cable_collision_length` 返回指定线束与其他线束发生干涉的中心线弧长。它利用线段 BVH 筛选候选，再求线段落在其他线束扩张胶囊体内的连续区间。同一线束的重叠区间合并计数，因此不会因对方被分成更多线段而重复计分。传入 `other_id` 可只计算与某条线束的关系。

`evaluate_cables` 返回 `before_length_mm`、`after_length_mm`、`improvement_pct`、`before_collides`、`after_collides`，比较一条候选路径与其他原路径。原干涉长度为零时，改善率为 `None`。`evaluate_chassis` 返回同样形式的字段，但针对箱体，只作为辅助指标。

`points` 是原路径副本。返回值为候选中心线数组。`validate_candidate` 检查路径数组格式、有限坐标、固定端点（误差不超过 1e-6 mm）和相邻点不重复。内部路径点和优化变量由小组设计，剩余干涉由评估工具计算。

返回形式为 `{31: candidate31, 22: candidate22}`，未返回的线束保留原路径。命令 `python main.py --joint --output solution.json` 调用此接口，保存多条提交并生成全场景报告。

同时改变多条线束时，需要用所有当前候选路径建立新的索引。例如在已读取 `bundles, occupancy, scene` 的程序中：

```python
trial_bundles = [{**item, "points": candidates.get(item["id"], item["points"])}
                 for item in bundles]
trial_index = InterferenceIndex(trial_bundles, occupancy, scene)
total_length = sum(trial_index.cable_collision_length(item["id"])
                   for item in trial_bundles)
```

原索引上的逐条候选查询不会自动把其他线束也替换成候选路径。分段或联合优化的最终比较都交给 `evaluate.py` 统一重建完整场景，避免漏掉对未修改线束的影响。

## 提交与独立评估

单条格式（下面的省略号需替换为完整数值点）：

```text
{"format":"BundleAvoidanceSubmission", "units":"Millimeters",
 "bundle_id":31, "points":[...]}
```

多条格式：

```text
{"format":"BundleAvoidanceSubmissionSet", "units":"Millimeters",
 "bundles":[{"id":31,"points":[...]}, {"id":22,"points":[...]}]}
```

只提交实际修改的线束即可，其余保留原路径；也允许提交全部 30 条。重复或未知 ID、非法路径、改写宽度等会被拒绝。基线和评估命令：

```powershell
python evaluate.py --output baseline_check.json
python evaluate.py --solution solution.json --output evaluation.json
```

报告的 `primary_metric` 为 `cable_collision_length`。`total_before_length_mm`、`total_after_length_mm`、`total_improvement_pct` 均指线束间主指标；`bundles` 中的 `before_length_mm`、`after_length_mm` 也是线束间干涉长度。主指标合并同一线束上的重复区间后，对全部 30 条分别求和，不除以二。

`before_pair_count`、`after_pair_count`、`new_pairs`、`removed_pairs` 记录干涉对数与关系变化。每对无序 ID 只计一次。`chassis_before_length_mm`、`chassis_after_length_mm`、`chassis_improvement_pct` 独立记录箱体辅助指标，不能代替主指标。

`submitted_improvement_pct` 仅供观察提交子集，正式比较使用 `total_improvement_pct`。即使一条线束未被修改，其他线束移动后，其干涉长度也会重新计算。两种改善率均以相应原始长度之和为分母，不能求各线束改善百分比的简单平均。改善率可能为负。

`sampled_max_displacement_mm` 以归一化弧长对齐的 1001 个采样点计算，是可重复的采样统计，不是严格的连续最大距离或 Hausdorff 距离。`evaluation_seconds` 不包含学生优化过程，搜索耗时和适应度评估次数需要自行记录。

## 可视化

安装 `requirements.txt` 后，运行`python visualize.py` 调用同一个查看器。

全部参数位于 `view_bundles.py` 头部：

| 参数 | 用途 |
|---|---|
| `SOLUTION_FILE` | None 查看输入；设为 `ROOT / "solution.json"` 查看原始与提交结果 |
| `BUNDLE_IDS`、`BUNDLE_COUNT` | 按 ID 筛选，再取前 N 条；None 表示全部 |
| `SHOW_VOXELS` | 显示箱体表面点云，默认 False |
| `SHOW_AXES` | 显示坐标轴 |
| `RADIUS_SCALE` | 显示半径倍率，默认 1.0；不改变数据或评估半径 |
| `CYLINDER_RESOLUTION`、`SPHERE_RESOLUTION` | 圆柱和球体网格精度 |
| `MAX_VOXEL_POINTS` | 箱体点云显示上限 |
| `WINDOW_WIDTH`、`WINDOW_HEIGHT` | 每个窗口的大小 |
| `CAMERA_FILE`、`SCREENSHOT_DIR` | 相机文件和截图保存目录 |

加载提交后打开两个同步窗口，分别显示原始和提交路径；未提交线束仍显示原路径。在任一窗口拖动、缩放或平移时，另一个窗口跟随视角。关闭任一窗口结束查看。

按 `S` 导出截图，单窗口保存 `preview.png`，双窗口分别保存 `comparison_before.png`、`comparison_after.png`。按 `C` 保存视角到 `view_camera.json`；启动时若该文件存在则自动读取。需要恢复自动取景时，移走该相机文件后重启。默认缩放同时考虑前后路径的范围，便于对比。

Open3D 查看需要可用的图形显示环境。胶囊网格是离散绘制，箱体点云经过采样，最终几何验收以连续查询为准。
